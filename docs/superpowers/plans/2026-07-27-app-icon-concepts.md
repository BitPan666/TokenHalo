# TokenHalo 应用图标候选稿实施计划

> **供智能代理执行：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐项执行本计划。所有步骤使用复选框跟踪。

**目标：** 生成并展示四个符合已确认视觉方向的 TokenHalo 应用图标候选稿。

**实现方式：** 使用内置图像生成能力分别生成 A–D 四张独立方形图，避免同一张拼图导致方案之间相互污染。生成结果仅作为预览稿保存到项目设计目录，不修改 `src-tauri/icons`；完成后检查构图、文字污染、蓝色渐变、小尺寸轮廓和四稿之间的差异。

**技术栈：** 内置图像生成工具、PNG、macOS 圆角方形应用图标构图。

## 全局约束

- 主色为深钴蓝到明亮天蓝的蓝色渐变。
- 不使用文字、字母、品牌名称、Codex 结形标志、水印或货币符号。
- 四张图均使用圆角方形画布、简洁几何和充足负空间。
- 图形需要在 `32×32` 像素下保持可辨认的轮廓。
- 本轮不修改 `src-tauri/icons`，不构建安装包，不发布版本。
- 所有交付说明和项目文档默认使用中文。

### 任务 1：生成四个独立候选图标

**文件：**
- 新建：`docs/icon-concepts/tokenhalo-icon-a.png`
- 新建：`docs/icon-concepts/tokenhalo-icon-b.png`
- 新建：`docs/icon-concepts/tokenhalo-icon-c.png`
- 新建：`docs/icon-concepts/tokenhalo-icon-d.png`

**接口：**
- 输入：`docs/superpowers/specs/2026-07-27-app-icon-concepts-design.md` 中的 A–D 视觉定义。
- 输出：四张相同尺寸的独立 PNG 候选稿，供下一任务检查和用户选择。

- [ ] **步骤 1：生成 A｜轻玻璃：光环仪表**

使用内置图像生成工具，采用以下约束：蓝色渐变圆角方形底板；不完整额度光环；
中央小型发光核心；克制玻璃高光；无文字、无字母、无水印、无 Codex 结形标志。

- [ ] **步骤 2：生成 B｜轻玻璃：悬浮统计**

使用内置图像生成工具，采用以下约束：蓝色渐变圆角方形底板；半透明光环包围三根
上升柱；轻盈悬浮；浅层纵深；无文字、无字母、无水印、无 Codex 结形标志。

- [ ] **步骤 3：生成 C｜纯扁平：双周期仪表**

使用内置图像生成工具，采用以下约束：蓝色渐变圆角方形底板；两层同心额度圆弧；
清晰矢量轮廓；无玻璃纹理；无文字、无字母、无水印、无 Codex 结形标志。

- [ ] **步骤 4：生成 D｜纯扁平：Token 脉冲**

使用内置图像生成工具，采用以下约束：蓝色渐变圆角方形底板；抽象 Token 圆盘结合
极简脉冲或上升指示；强轮廓；无货币或区块链暗示；无文字、无字母、无水印。

### 任务 2：检查、保存并向用户展示

**文件：**
- 检查：`docs/icon-concepts/tokenhalo-icon-a.png`
- 检查：`docs/icon-concepts/tokenhalo-icon-b.png`
- 检查：`docs/icon-concepts/tokenhalo-icon-c.png`
- 检查：`docs/icon-concepts/tokenhalo-icon-d.png`

**接口：**
- 输入：任务 1 生成的四张候选稿。
- 输出：通过视觉检查的四张预览图及中文方案说明。

- [ ] **步骤 1：逐张检查视觉约束**

检查每张图是否为完整方形图标、是否出现文字或水印、是否保持蓝色主色，以及 A–D
的核心图形是否分别对应光环仪表、悬浮统计、双周期仪表和 Token 脉冲。

- [ ] **步骤 2：检查小尺寸轮廓**

将四张候选稿按 `32×32` 视觉尺寸预览，确认主体没有因细节过多而消失。若某一方案
无法识别，只针对该方案重新生成一次，并减少内部细节。

- [ ] **步骤 3：确认项目影响范围**

运行：

```bash
git status --short
git diff -- src-tauri/icons
```

预期结果：只出现设计文档、计划和 `docs/icon-concepts` 候选图片；`src-tauri/icons`
没有任何变化。

- [ ] **步骤 4：展示候选稿并等待选择**

在回复中按 A–D 顺序嵌入四张图片，分别用一句中文解释功能隐喻，并明确推荐 A 的
理由。等待用户选择后再编写正式图标替换计划。
