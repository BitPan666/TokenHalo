# 状态分组任务胶囊网页版交互设计

**日期：** 2026-08-11

**状态：** 交互方向已确认，待书面规格复核

**交付顺序：** 先完成网页版交互预览，确认后再接入桌面通知窗口

## 背景

现有多任务胶囊把任务逐条平铺，最多显示三条，其余内容使用 `+N` 表示。该方式存在三个问题：

- 用户无法从 `+N` 判断隐藏的是哪种状态；
- 正在工作、需要处理、任务完成和执行失败具有相同视觉重量；
- 多个同状态任务会占满可见区域，挤压更重要的状态。

本设计以“外层按状态、内层按任务”的两级结构取代逐任务平铺。四种状态最多各占一个外层位置；同状态的多个任务在该状态卡片背后折叠。

本规格取代 `2026-08-10-multi-task-capsule-stack-design.md` 中“最多三条任务加 `+N`”的展示与展开规则。未被本规格修改的窗口定位、透明背景、悬浮球内呼吸灯和本机隐私边界继续有效。

## 目标

- 默认只展示最高优先级状态中的最新任务。
- 鼠标进入外层区域后，一次看清当前存在的最多四种状态。
- 同状态多任务使用可理解的层叠和明确数量，不再使用脱离上下文的 `+N`。
- 点击状态组后可以查看该状态的具体任务。
- 关闭操作只影响当前任务，不会误删整个状态组。
- 保留单卡悬停操作，同时减少常驻按钮带来的视觉噪声。
- 新胶囊出现、展开和关闭都不抢走其他应用的输入焦点。

## 非目标

- 不把胶囊改造成完整任务管理器。
- 不提供跨状态搜索、筛选、批量关闭或一键清空。
- 不在网页版中连接真实 Codex 事件或启动真实应用。
- 不在本轮解决跳转到指定 Codex 任务的公开接口限制。
- 不改变任务事件的本机处理和隐私边界。

## 信息架构

任务提醒分成两层：

1. **状态层：** 需要处理、执行失败、任务完成、正在工作。
2. **任务层：** 属于同一状态的具体任务，按事件时间从新到旧排列。

状态优先级固定为：

1. 需要处理；
2. 执行失败；
3. 任务完成；
4. 正在工作。

同一个任务只保留当前状态。状态变化更新原任务，不新增重复任务卡片。

## 外层默认态

- 只完整显示当前最高优先级状态组的最新任务。
- 如果该状态只有一条任务，不显示层叠背板和数量。
- 如果该状态有多条任务，背后最多露出两层同色背板。
- 状态标题使用 `状态名称 · 数量`，例如 `需要处理 · 3`，数量明确属于该状态。
- 最上层任务显示清洗后的任务名称；不显示对话正文、技能调用、Markdown 链接或本机路径。
- 胶囊保持与悬浮球贴身侧挂，悬浮球位置不移动。

## 外层悬停展开

鼠标进入整个胶囊区域后，展开当前存在的状态组：

- 每种状态最多出现一张状态卡，因此最多四张。
- 不存在任务的状态不占位置。
- 状态卡仍按固定优先级排列，不因悬停改变顺序。
- 每张状态卡只显示该状态最新任务；同状态多任务继续以背板和数量提示。
- 任意时刻只有鼠标所在的任务卡显示操作。
- 鼠标离开整个胶囊包围区域后延迟约 160ms 收起；重新进入会取消收起。
- 键盘焦点仍在胶囊区域内时不收起；按 `Escape` 返回外层默认态。

## 状态组点击展开

- 点击含有多条任务的状态卡，展开该状态的任务列表。
- 同一时间只能展开一个状态组。
- 最新任务位于最上方，旧任务依次向远离悬浮球的方向排列。
- 组内最多直接显示四条任务；超过四条时在该组内部滚动，不增加外层窗口高度。
- 其他状态组保持可见但不展开，避免用户丢失整体状态上下文。
- 再次点击状态标题、按 `Escape` 或鼠标离开整个区域，关闭组内列表。
- 单任务状态卡不可进入组内展开态，点击卡片本身不产生无意义切换。

## 关闭与操作

原来的文字“忽略”按钮由右上角关闭按钮取代。

### 关闭按钮

- 使用半透明浅色圆形底和 `×` 图标，视觉尺寸约 24 逻辑像素。
- 默认隐藏；当前任务卡被鼠标悬停或键盘聚焦时显示。
- 位于任务卡右上角，左侧继续保留状态圆点和文本阅读起点。
- 在折叠状态组上点击关闭，只关闭当前最上面的最新任务。
- 关闭后，同状态的下一条任务自动成为顶层任务。
- 组内展开时，每条任务拥有自己的关闭按钮。
- 不提供关闭整个状态组或一次清空全部任务。

### 状态操作

| 状态 | 主操作 | 辅助操作 | 关闭按钮 |
| --- | --- | --- | --- |
| 正在工作 | 前往 Codex | 无 | 有 |
| 需要处理 | 前往 Codex | 稍后提醒 | 有 |
| 任务完成 | 前往 Codex | 无 | 有 |
| 执行失败 | 前往 Codex | 无 | 有 |

主操作和辅助操作继续只在任务卡悬停或键盘聚焦时出现。关闭按钮和操作按钮点击都不得触发状态组展开或收起。

网页版中的“前往 Codex”只展示点击反馈，不启动外部应用；桌面版继续根据实际能力前台激活 Codex，不能定位任务时不得宣称已打开指定任务。

## 状态生命周期

- **正在工作：** 任务运行期间保留；进入其他状态后由新状态替换。
- **需要处理：** 保留到任务继续、用户稍后提醒或关闭。
- **执行失败：** 保留到新任务状态替换、用户查看或关闭。
- **任务完成：** 显示约 6 秒后自动移除；用户悬停、键盘聚焦或展开状态组时暂停倒计时。
- **稍后提醒：** 需要处理任务隐藏 10 分钟；到期后重新进入原状态组，除非任务已继续或结束。

新事件到达时更新状态组，但不抢键盘焦点。若用户正在查看某一状态组，新任务可以加入该组并显示数量变化，不强制关闭当前展开态。

## 视觉规则

- 四种状态沿用现有颜色：正在工作为蓝色、需要处理为琥珀色、任务完成为绿色、执行失败为珊瑚红。
- 颜色只作为辅助线索，卡片始终显示完整状态文案。
- 同状态背板使用相同状态色的细微边缘，不使用矩形窗口阴影或向外发光。
- 卡片保持现有玻璃质感、圆角和文字层级。
- 主操作按钮沿用浮层蓝色和顶部偏白透明高光。
- 关闭按钮的视觉重量低于主操作按钮，悬停时才提高对比度。
- 减少动态效果模式下取消位移动画，直接切换布局和透明度。

## 网页版交互预览

网页版作为独立设计验证面，不连接真实任务数据。它提供固定、可重复的模拟场景：

- 单一正在工作任务；
- 四种状态同时存在；
- 同一状态含一条、两条、四条和五条任务；
- 需要处理任务的稍后提醒；
- 关闭顶层任务后下一条自动补位；
- 任务完成倒计时暂停与恢复；
- 新任务到达当前展开组；
- 减少动态效果；
- 悬浮球位于屏幕上、下、左、右附近的布局。

预览页包含一个不进入成品界面的开发控制区，用于切换模拟场景、悬浮球位置和动态效果。成品胶囊本身不显示测试按钮或调试文案。

## 组件边界

### 状态分组选择器

输入完整任务状态，输出按优先级排列的状态组和每组按时间排列的任务。它是纯数据逻辑，不依赖 React 或窗口 API。

### 外层状态堆叠

负责默认态、外层悬停展开、共享热区、键盘焦点和离开延迟。它不负责修改任务状态。

### 状态组

负责同状态背板、数量、组内展开和内部滚动。它只允许一个组展开，并将任务级操作向上发送。

### 单任务胶囊

负责状态文案、任务名称、时长、关闭按钮和悬停操作。它不知道外层优先级，也不能关闭整个状态组。

### 网页预览控制器

负责构造模拟事件和切换预览场景。它与正式任务数据桥接完全隔离，生产桌面构建不依赖调试控制器。

## 数据流

1. 模拟器或桌面事件桥接产生任务事件。
2. reducer 按任务标识更新、替换或移除当前状态。
3. 状态分组选择器按状态优先级和任务时间生成分组。
4. 外层堆叠默认选择第一组，悬停时展示最多四组。
5. 用户点击某一状态组后，仅展开该组的任务。
6. 关闭、稍后提醒和前往 Codex 操作携带当前任务标识返回 reducer 或桌面桥接。
7. 状态更新后重新分组；关闭顶层任务时同组下一条自动补位。

## 异常与降级

- 屏幕无法容纳四个状态组：保持最高优先级组完整，其余组压缩为状态摘要条，不移出工作区。
- 展开组内任务超过可用高度：固定组内最大高度并滚动，不移动悬浮球。
- 窗口尺寸更新失败：回退到最高优先级单卡，同状态数量仍显示在标题中。
- 任务名称无效：回退到项目名称，再回退到 `Codex 任务`。
- 外部应用前台激活失败：按钮给出轻量失败反馈，不自动关闭任务卡。
- 当前顶层任务在操作过程中已被新状态替换：忽略过期操作，不影响新任务。

## 可访问性

- 状态组向读屏器报告状态名称和任务数量。
- 关闭按钮提供包含任务名称的标签，例如“忽略任务：修复登录问题”。
- 键盘可依次访问状态组、任务、主操作、稍后提醒和关闭按钮。
- `Enter` 或空格展开状态组，`Escape` 逐层返回。
- 组内滚动区域保持清晰焦点顺序，不形成键盘陷阱。
- 动画、计时和实时状态变化遵循减少动态效果设置。
- 不仅依赖颜色区分状态。

## 测试要求

### 数据与状态

- 四状态优先级和同状态时间排序。
- 同一任务状态更新不会生成重复任务。
- 状态组数量与任务数量准确。
- 关闭顶层任务后同组下一条补位。
- 关闭单条不会删除整个状态组。
- 稍后提醒到期和终态覆盖行为。

### 网页交互

- 默认只显示最高优先级状态组。
- 外层悬停展示一至四个现存状态组。
- 多任务状态卡显示背板和明确数量。
- 点击只展开目标状态组，且同一时间仅一组展开。
- 组内四条直接展示，五条以上使用内部滚动。
- 离开共享区域后稳定收起，不因卡片间隙闪烁。
- 关闭与操作按钮不触发父级展开。
- 操作只在当前悬停或聚焦任务上显示。
- 减少动态效果和完整键盘操作。

### 桌面接入前验收

- 网页预览在常用桌面尺寸下不裁切悬浮球或胶囊。
- 四种悬浮球位置都能保持贴身侧挂和安全展开方向。
- 新通知不会抢输入焦点。
- 透明区域不出现矩形阴影或窗口级底色。
- 正式接入时沿用同一分组选择器和前端组件，不复制第二套状态规则。

## 验收标准

- 用户无需理解 `+N` 即可知道每种状态各有多少任务。
- 默认态始终显示最高优先级状态中的最新任务。
- 外层最多展示四个状态组，顺序稳定。
- 同状态多任务在背后折叠，点击后可以查看具体任务。
- 关闭按钮只关闭当前任务，下一条自动补位。
- 任意时刻最多展开一个状态组。
- 操作按钮和关闭按钮仅在当前任务悬停或聚焦时显示。
- 完成倒计时在用户交互期间暂停，离开后恢复。
- 网页预览覆盖主要状态、溢出、位置和键盘交互。
- 网页方案确认前不修改真实桌面通知行为。
