# 本机 Token 统计与原生毛玻璃设计

## 目标

在现有 macOS Codex 额度浮层中增加第二个展开页面，让用户通过卡片右上角图标在“剩余额度”和“本机 Token 统计”之间切换。

第一版验收目标：

- 保留现有 100×100 悬浮球和 320×320 剩余额度卡片。
- 新增 400×400 Token 统计卡片。
- 统计当前用户 `~/.codex/sessions` 中可读取的本机日志。
- 提供每日、每周、每月三种聚合粒度。
- 使用真正透出桌面颜色的 macOS 原生毛玻璃。
- 透明度和模糊强度可由用户调整并持久化。
- 保留现有跨普通 Space、其他应用原生全屏 Space、贴边反向展开和单窗口行为。

## 数据边界与免责声明

统计数据只来自当前 Mac 上可读取的 Codex 会话日志。应用只解析 Token 计数记录，不采集、缓存或上传用户的提示词、回复正文、代码内容或文件内容。

统计卡片和项目 README 必须明确说明：

- 仅统计本机可读取的 Codex 日志；
- 可能遗漏云端、其他设备或已经删除的记录；
- 日志格式或记录缺失可能导致统计不完整；
- 结果只用于观察本机使用趋势，不代表官方账单、账户级用量或剩余额度；
- 数据和统计缓存全部保留在本机，不上传。

统计失败不得影响现有额度查询功能。

## 已确认的产品行为

### 卡片状态

同一个 `widget` 窗口具有三个视觉尺寸：

| 状态 | 尺寸 | 内容 |
| --- | --- | --- |
| 收起 | 100×100 | 现有额度悬浮球 |
| 剩余额度 | 320×320 | 现有额度卡片 |
| Token 统计 | 400×400 | 新增统计卡片 |

悬浮球 Hover 后展开为用户上一次使用的页面。首次安装默认进入剩余额度页。点击卡片右上角的页面切换图标，在剩余额度和 Token 统计之间切换，并同时调整原生窗口尺寸。

鼠标离开任一展开页面后仍收起为 100×100 悬浮球。应用运行期间记住最后使用的展开页面；该选择写入偏好设置，重启后继续生效。

### 贴边展开

现有水平和垂直独立锚点模型继续使用，但展开目标尺寸由页面决定：

- 剩余额度页使用 320×320；
- Token 统计页使用 400×400。

从 320×320 切换到 400×400，或从 400×400 切换回 320×320 时，继续保留当前锚点：

- 靠右时向左增长或收缩；
- 靠下时向上增长或收缩；
- 右下角同时向左、向上变化；
- 最终位置始终限制在当前显示器可用工作区内。

用户拖动展开卡片后，收起位置按拖动后的窗口位置与当前锚点重新计算。第一版仍只支持一个浮层窗口，不为外接显示器复制实例。

## 统计页面

### 聚合粒度

“每日 / 每周 / 每月”表示聚合单位，不表示“今天 / 本周 / 本月”。

#### 每日

- 默认显示最近 30 个自然日；
- 每根柱子代表一个自然日；
- 最右侧为今天；
- 没有使用记录的日期显示为零；
- 跨月时仍保持连续 30 天，不按月截断。

#### 每周

- 默认显示最近 12 个自然周；
- 每根柱子代表一个自然周；
- 自然周从周一开始，到周日结束；
- 标签使用本地化周序号，例如“第 28 周”或 `W28`；
- 最右侧为包含今天的当前自然周。

周序号和跨年归属采用 ISO week-date 规则，以避免元旦附近的周编号歧义。

#### 每月

- 显示当前自然年的 1 月至 12 月；
- 每根柱子代表一个自然月；
- 尚未到来的月份保留位置并显示为零或弱化状态；
- 当前月包含截至当前时刻的累计值。

### 柱子交互

默认选中最右侧的有效周期。点击任意柱子后：

- 主数据切换为该日、该周或该月的总 Token；
- 明细切换为该周期的输入、输出、缓存输入、任务数和峰值任务；
- 选中柱显示明确但克制的高亮；
- 切换聚合粒度时，选中项回到最新有效周期。

卡片不使用横向滚动。30 根日柱、12 根周柱和 12 根月柱都在固定图表宽度内自适应分配宽度和间距。日期标签只显示起点、若干关键节点和终点，避免文字重叠；完整周期名称通过 Hover 提示和辅助功能标签提供。

### 指标定义

- **总 Token**：该周期内所有有效增量 Token 的总和。
- **输入**：输入 Token 增量总和。
- **输出**：输出 Token 增量总和。
- **缓存输入**：缓存输入 Token 增量总和。它作为输入的组成部分单独展示，不再叠加进总 Token。
- **任务数**：该周期内产生正 Token 增量的不同 Codex 会话数量。
- **峰值任务**：该周期内单个会话累计 Token 最大值。

数值采用紧凑格式，如 `842K`、`5.25M`、`1.2B`。单位后缀与主数字保持同一基线。

## 日志解析与差量算法

### 数据源

后端从当前用户主目录自动解析：

```text
~/.codex/sessions
```

不得硬编码开发者用户名或绝对路径。目录不存在、不可读或没有 Token 记录时返回结构化空状态，而不是把它当作额度接口错误。

解析器逐行读取 JSONL，只处理 Token 计数相关记录及以下数值：

- 时间戳；
- `total_token_usage`；
- `last_token_usage`；
- input；
- cached input；
- output；
- reasoning；
- total。

其他事件内容不反序列化为业务模型，也不进入统计缓存。

### 避免重复统计

同一会话中的 `total_token_usage` 是累计值。每个字段使用相邻累计值的非负差量计入时间桶：

1. 当前累计值大于或等于上一累计值时，计入差值。
2. 当前累计值小于上一累计值时，视为累计序列重置，并以当前值开始新的差量段。
3. 字段缺失时不推导虚假值；只使用该记录中可靠的字段。
4. 明确提供的 `last_token_usage` 可用于校验累计差量，但不得与累计差量重复相加。
5. 一条增量按该记录时间戳和本机时区归入对应自然日。

reasoning Token 保留在内部数据模型中用于兼容日志字段，但第一版卡片不单独展示；总 Token 仍以日志的可靠总量差值为准。

### 时区

所有日、周、月边界都使用当前系统本地时区。应用启动、系统时区变化或夏令时变化后重新计算受影响的时间桶。时间戳解析失败的记录被跳过并计入非敏感诊断计数，不输出原始日志内容。

## 增量索引与缓存

采用 Rust 后端增量统计，不让 React 前端直接读取会话文件。

本地缓存保存：

- 日志文件的稳定路径标识；
- 文件长度与修改时间；
- 已处理字节位置；
- 当前会话各累计字段的最后值；
- 会话已归属的日期桶与累计贡献；
- 最近每日聚合结果；
- 索引格式版本和最后更新时间。

缓存不得保存原始 JSON 行、提示词、回复文本或认证信息。

### 更新策略

- 第一次打开统计页时完成全量建立索引。
- 应用启动后可在后台预热，但不得阻塞额度卡片显示。
- 统计页可见时每 60 秒执行一次轻量增量扫描。
- 用户切换到统计页时立即触发一次增量扫描。
- 新文件从头读取；增长文件从已处理位置继续；未变化文件跳过。
- 文件缩短、内容替换、索引版本变化或关键元数据不一致时，重新解析该文件并修正它影响的时间桶。
- 文件被删除时，从聚合结果中移除该文件之前贡献的数据。
- 写缓存使用临时文件加原子替换，读取失败时保留旧缓存备份并可安全全量重建。

全量重建和增量扫描在单个后端任务中串行执行，避免并发扫描重复写入。前端重复请求返回同一进行中任务或最近一次可用快照。

## 后端接口与模型

新增独立于额度快照的数据模型：

```text
TokenStatsSnapshot
  status: ok | empty | stale | unavailable
  granularity: day | week | month
  buckets[]
  selected/latest summary
  updatedAt
  message?
```

每个 bucket 至少包含：

```text
key
label
rangeStart
rangeEnd
totalTokens
inputTokens
cachedInputTokens
outputTokens
reasoningTokens
taskCount
peakTaskTokens
isFuture
```

Tauri 命令：

- 获取指定聚合粒度的最近统计快照；
- 强制或普通增量刷新；
- 获取和更新已有 Widget 偏好设置。

统计刷新结果可以通过独立事件通知 React。额度查询、刷新退避和错误状态保持原有路径，不与统计状态合并。

## 前端状态与组件

`App` 增加展开页面状态：

```text
expandedView: quota | tokenStats
statsGranularity: day | week | month
selectedBucketKey
```

Token 统计页面拆为独立组件，至少包含：

- 标题与更新时间；
- 设置/说明入口；
- 页面切换按钮；
- 每日、每周、每月 segmented control；
- 主 Token 数值；
- 当前选中周期与任务数；
- 柱状图；
- 输入、输出、缓存输入、峰值任务明细；
- 常驻的简短数据免责声明；
- loading、empty、stale 和 unavailable 状态。

柱状图使用语义化 HTML/CSS 实现，不引入大型图表依赖。每根柱子是可聚焦按钮，支持键盘选择，并提供包含周期、Token 和任务数的可访问名称。

## 视觉规格

### 已确认默认值

- Token 统计卡片：400×400。
- 玻璃透明度：40%。
- 模糊强度：预览基准 40。
- 渐变边框高光强度：固定 50%。
- 边框：2px 环形渐变描边，渐变不得覆盖卡片内部。
- 主数值：高字重、深色，保留克制的顶部高光细节。
- `M` 等单位后缀：中性灰 `#737B86`。
- 激活 Tab：顶部深蓝 `#3779DF`，向底部过渡为浅色半透明蓝 `rgba(91, 171, 255, 0.72)`。
- 柱状图：顶部深蓝 `#3C7FE7`，向底部过渡为浅色半透明蓝 `rgba(103, 184, 255, 0.60)`。
- 图标、任务数、明细行和说明区域保持扁平，不叠加多层高光、阴影或拟物卡片。

### 原生毛玻璃

macOS 26 及以上优先使用 `window-vibrancy` 的 Liquid Glass 能力，使桌面内容参与模糊、染色和透明效果。旧版 macOS 使用原生 Vibrancy 作为兼容路径。

HTML、Body、Webview 和原生窗口背景都必须透明。CSS 只负责浅蓝染色、渐变描边和内部 UI，不用一张不透明渐变伪装毛玻璃。

用户设置开放：

- **玻璃透明度**：连续调整浅蓝染色/玻璃透光观感；
- **背景模糊强度**：macOS 26 映射到原生可调玻璃半径，旧版 macOS 映射到有限的 Vibrancy 兼容档位。

边框高光固定为 50%，不暴露为用户设置。默认值以确认后的 40% / 40 / 50% 方案为准。不同 macOS 版本的原生渲染允许存在轻微视觉差异，设置说明中应予以告知。

## 设置与持久化

扩展 `WidgetPreferences`，增加向后兼容的默认字段：

```text
expandedView = quota
glassTransparency = 40
glassBlurStrength = 40
```

Rust 端对范围做归一化，前端只保存合法值。老版本配置缺少字段时自动使用默认值，不破坏现有 locked、alwaysOnTop、pinnedProvider、autoRotateSeconds 和 language。

设置与说明面板从统计卡片右上角入口打开，包含两个外观控件、恢复默认值操作、数据来源说明和统计风险提示。拖动滑块时即时预览，松开后持久化；写入失败时恢复上一次保存值并显示非阻塞提示。

原生毛玻璃效果的更新由 Rust/macOS 窗口层执行，CSS 变量由 React 同步更新。二者使用同一份规范化偏好值。

## 错误与空状态

- **empty**：目录不存在、没有日志或没有 Token 记录，显示“暂无本机 Token 统计”。
- **stale**：刷新失败但存在旧快照，继续展示旧数据并标注“数据可能已过期”。
- **unavailable**：没有旧数据且目录不可读或索引无法建立，显示简短原因和重试操作。
- **部分文件损坏**：跳过损坏行或文件，继续汇总其余数据，并在说明中标注统计可能不完整。
- **设置更新失败**：恢复原值，不影响统计和额度页面。
- **原生毛玻璃失败**：退化为透明浅蓝 CSS 背景，保留可读性和窗口功能，同时记录不含敏感内容的诊断错误。

错误信息不得包含认证 Token、原始 JSON、提示词、账户 ID 或完整用户目录路径。

- 不提供官方账单级或账户级精确 Token 数据。
