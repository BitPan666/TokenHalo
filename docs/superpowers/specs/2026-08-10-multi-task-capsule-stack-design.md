# 多任务胶囊堆叠设计

**日期：** 2026-08-10

**状态：** 交互方向已确认，待书面规格复核
**目标体验版：** `v0.1.7-beta.1`

## 背景

现有任务提醒每次只显示一个胶囊。当多个 Codex 任务同时运行、完成、失败或等待输入时，用户无法直接感知“还有几条”，只能等待队列依次播放。

本次迭代将单胶囊改为“宠物式堆叠”：收起时仅完整展示最高优先级任务，后续胶囊只露出边缘；用户 Hover、点击或使用键盘聚焦时展开可见任务。

## 目标

- 用户在收起态即可感知存在多条任务。
- 保持单胶囊的轻量感，避免多个通知同时铺满屏幕。
- 保留原有的单卡 Hover 操作按钮。
- 重要任务不会被运行中或已完成任务遮挡。
- 胶囊展开时不移动悬浮球，不遮挡悬浮球。
- 将多任务交互覆盖到自动化测试和设备验收中。

## 非目标

- 不在胶囊中做完整任务管理器。
- 不新增分组、搜索、筛选或批量操作。
- 不在第一版展示超过三张完整胶囊。
- 不改变现有任务状态的业务定义和隐私边界。
- 不因为堆叠展开而改变悬浮球的位置。

## 方案选择

已比较三种方案：

1. 单条轮播：最安静，但无法直接感知多任务。
2. 胶囊堆叠：信息直接，不需要理解聚合规则。
3. 优先任务加状态聚合：低打扰，但概念和操作层级较多。

最终选择第二种，并通过默认收起、最多三层和移出自动收起控制占屏与打扰。

## 排序与队列

任务优先级保持现有规则：

1. 需要输入。
2. 任务失败。
3. 任务完成。
4. 正在工作。

同一优先级内最新任务排在前面。一个任务仅保留当前状态，新状态替换该任务的旧状态。

胶囊窗口最多完整展示三条，其余任务保留在队列中。当队列超过三条时，最上层显示 `+N`。该数字表示当前未完整展示的任务数量。当可见任务消失、被忽略或进入新状态时，队列自动补位。

等待输入和未处理失败不会被普通状态挤出队列。普通状态仍使用现有的队列上限和清理规则。

## 收起态

- 最高优先级胶囊完整显示。
- 第二、第三条各露出约 10-12 逻辑像素的边缘。
- 后层使用轻微位移和尺度差形成叠放感，不使用外发光。
- 最上层继续显示状态、任务名称和时长。
- 仅有一条任务时，不显示后层或 `+N`。
- 可见层数与 `+N` 为视觉补充，悬浮球上的数字徽标仍只统计需要输入和失败的未处理任务。

## 展开与收起交互

### 展开条件

以下任一条件触发展开：

- 鼠标进入整个胶囊堆叠区域。
- 用户点击堆叠区域。
- 任意一张胶囊或其操作按钮获得键盘焦点。

展开动画使用位移和透明度，时长约 220-280ms。不为了视觉效果改变任务排序。系统开启减少动态效果时，立即切换状态。

### 收起条件

- 鼠标离开整个堆叠区域时自动收起。
- 为避免胶囊之间的空隙导致闪烁，整个展开包围盒共享一个 Hover 热区。
- 鼠标离开后延迟约 160ms 收起；期间重新进入则取消收起。
- 点击只负责触发展开，不锁定展开态。
- 键盘焦点仍在堆叠区域内时不收起；焦点完全离开后收起。

## 单卡操作

原有单胶囊 Hover 交互必须保留：

- 堆叠展开后，仅当前 Hover 或键盘聚焦的胶囊显示按钮。
- 其他可见胶囊保持文本状态，不同时展示按钮。
- 从单张胶囊移入另一张时，按钮跟随当前 Hover 卡片切换。
- 鼠标仍在堆叠区域内时，单卡按钮隐藏不会导致整个堆叠收起。
- 点击操作按钮不触发堆叠的点击展开处理。

按钮保持现有状态规则：

| 状态 | 主操作 | 次操作 |
| --- | --- | --- |
| 正在工作 | 打开 Codex | 无 |
| 需要输入 | 打开 Codex | 稍后提醒 |
| 任务完成 | 打开 Codex | 忽略 |
| 任务失败 | 打开 Codex | 忽略 |

## 计时规则

- 正在工作、任务完成和任务失败保留现有的 2 秒、7 秒和 12 秒显示时长。
- 需要输入不自动过期。
- 定时器从任务进入可见队列时开始，不因后层仅露出边缘而停止。
- 堆叠处于 Hover、键盘聚焦或点击展开期间，所有可见胶囊的自动过期计时暂停。
- 移出或失去焦点后恢复剩余时长，保证用户有机会点击操作。
- 不可见的普通队列项不新建独立的胶囊计时器；当其进入可见三条时再按对应状态开始显示计时。

## 窗口尺寸与位置

`task-toast` 仍为独立透明窗口，但需从固定单卡尺寸改为按状态动态调整：

- 单卡或收起堆叠使用最小所需窗口。
- 展开三卡时增加窗口尺寸，不通过一个始终很大的透明窗口预留空间。
- 窗口尺寸变化前重新计算工作区和可见面积，避免超出屏幕。
- 靠近悬浮球的锚点卡片在展开前后保持位置稳定。
- 其他卡片向远离悬浮球的方向展开。

方向规则：

- 胶囊在悬浮球上方时，卡片向上展开。
- 胶囊在悬浮球下方时，卡片向下展开。
- 胶囊在悬浮球左右侧时，优先向剩余空间更大的垂直方向展开。
- 若展开三卡无法完整放入当前工作区，降级为两卡可见加 `+N`。
- 若两卡仍无法放入，降级为单卡加 `+N`，但不移动悬浮球。

窗口边缘保持透明，不恢复外投影或窗口级模糊层。

## 组件与责任

### 队列选择器

输入完整任务状态，输出：

- 按优先级排序的可见条目；
- 未完整展示数量；
- 悬浮球状态与未处理注意事项数量。

排序和数量计算保持为纯函数，不依赖 React 或桌面窗口。

### 堆叠容器

负责收起、展开、Hover 热区、键盘焦点和移出延迟，不负责任务优先级。

### 单任务胶囊

继续负责文案、时长、状态色和 Hover/键盘操作。单任务胶囊不感知自己在队列中的优先级。

### 窗口控制器

根据可见卡片数、收起/展开状态和当前方向计算窗口尺寸与位置。窗口调整失败时回退到单卡模式。

## 数据流

1. 本机任务观察器产生经过验证的任务状态。
2. 状态 reducer 按任务更新、去重并保留队列。
3. 队列选择器生成最多三条可见任务和 `+N`。
4. 主窗口将可见队列发送给 `task-toast` 窗口。
5. 堆叠容器渲染收起或展开布局。
6. 用户操作携带对应 `threadId` 返回主窗口。
7. reducer 更新目标任务，队列补位并重算窗口。

## 错误处理与降级

- 窗口扩展失败：回退单卡显示，任务仍保留在队列。
- 屏幕空间不足：降低可见卡片数，用 `+N` 告知剩余数量。
- 位置数据获取失败：使用当前方向和上次成功锚点，不移动悬浮球。
- 新任务在展开期间到达：队列按优先级更新，但展开态保持，避免整体突然收起。
- 当前 Hover 卡片被新状态移除：操作按钮隐藏，焦点移到堆叠容器，不触发错误操作。
- 任务打开能力不可用：保持现有的打开 Codex 或隐藏主操作降级。

## 可访问性

- 堆叠容器向读屏器报告可见任务数和队列剩余数。
- 每张胶囊保留独立 `status` 语义和完整文案。
- 键盘 Tab 进入堆叠后自动展开，按顺序访问每张胶囊的可用操作。
- `Escape` 将焦点退回堆叠容器并收起，不清除任务。
- 颜色不是唯一状态线索，每张胶囊继续显示状态文案。
- 减少动态效果模式禁用展开位移动画。

## 测试要求

### 队列与状态

- 四类状态的优先级与同级时间顺序。
- 最多三条可见任务和正确的 `+N`。
- 状态替换、去重、忽略、稍后提醒和队列补位。
- 重要任务不被普通队列清理。
- 悬浮球数字徽标与 `+N` 各自使用正确计数范围。

### 前端交互

- 单卡、两卡、三卡和超过三条的收起态。
- Hover、点击、键盘聚焦展开与移出延迟收起。
- 仅 Hover/聚焦单卡显示对应按钮。
- 按钮点击不冒泡到堆叠展开逻辑。
- 展开期间暂停计时，移出后恢复剩余时长。
- 新任务到达、当前卡片移除和队列补位时不闪烁。
- 减少动态效果与键盘访问。

### 窗口与位置

- 四个基本位置的锚点卡片保持。
- 上下位置向远离悬浮球的方向展开。
- 左右位置根据剩余空间选择向上或向下展开。
- 三卡、两卡和单卡降级尺寸不越出当前工作区。
- 动态调整失败回退单卡，队列不丢失。
- 窗口保持透明，无方形背景、外投影或模糊合成层。

### 桌面集成

- macOS 全桌面和全屏空间。
- Windows 缩放、多显示器和工作区。
- Codex 前台免打扰规则不变。
- 开发模拟与真实任务共用同一套堆叠组件。

## 验收标准

- 同时接收四种状态时，收起态首卡与队列优先级一致。
- 两条及以上任务形成可识别的堆叠，不会误认为阴影。
- 展开后最多三张完整胶囊，其余任务以 `+N` 告知。
- 移出整个区域后稳定收起，卡片间移动不闪烁。
- 任意时刻仅一张胶囊显示操作按钮。
- 悬浮球位置不变，锚点卡片不跳动。
- 悬浮球周围状态光保持四周向内的窄呼吸效果，不恢复外发光。
- 胶囊窗口不出现方形背景。
- 现有单任务和通知设置流程不回归。
- 自动化测试、前端构建、Rust 测试、品牌一致性检查全部通过。
